Yes. On macOS, a clean command-line approach is **Docker Desktop + kind + kubectl + Helm**. `kind` creates Kubernetes nodes as Docker containers, which makes it excellent for local development and learning. The current official kind quick-start lists `v0.33.0` and supports installation with Homebrew; Kubernetes also documents `brew install kubectl` for macOS. ([kind][1])

## 1. Verify Docker is running

Docker Desktop needs to be installed and running. Docker currently supports installation on both Apple Silicon and Intel Macs. ([Docker Documentation][2])

```bash
docker version
```

Then:

```bash
docker info
```

Test Docker:

```bash
docker run --rm hello-world
```

You should see:

```text
Hello from Docker!
```

If Docker Desktop is installed but not running:

```bash
open -a Docker
```

Then check again:

```bash
docker ps
```

# 4. Create a Kubernetes cluster configuration

Create:

```bash
cat > kind-config.yaml <<'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4

name: docker-k8

nodes:

  # Kubernetes control plane
  - role: control-plane

    # Allow localhost:8080 to reach a NodePort
    extraPortMappings:
      - containerPort: 30080
        hostPort: 8080
        protocol: TCP

  # Worker node 1
  - role: worker

  # Worker node 2
  - role: worker
EOF
```

This creates:

```text
Mac
 |
 | Docker
 |
 +-------------------------------+
 |                               |
 | Kubernetes Cluster            |
 |                               |
 |  +-------------------------+  |
 |  | Control Plane           |  |
 |  | docker-k8-control-plane |  |
 |  +-------------------------+  |
 |                               |
 |  +-------------------------+  |
 |  | Worker                  |  |
 |  | docker-k8-worker        |  |
 |  +-------------------------+  |
 |                               |
 |  +-------------------------+  |
 |  | Worker                  |  |
 |  | docker-k8-worker2       |  |
 |  +-------------------------+  |
 |                               |
 +-------------------------------+
          |
          |
       port 8080
          |
       Browser
```

Think of it like a school:

* **Cluster** = the school
* **Control plane** = principal's office
* **Worker nodes** = classrooms
* **Pods** = students doing work
* **Deployment** = instructions saying how many students should be working
* **Service** = front desk that tells visitors where to go
* **kubectl** = your communication system with the principal

# 5. Create the cluster

Run:

```bash

  --name docker-k8 \
  --config kind-config.yaml
```

```text
Creating cluster "docker-k8" ...
 ✓ Ensuring node image
 ✓ Preparing nodes
 ✓ Writing configuration
 ✓ Starting control-plane
 ✓ Installing CNI
 ✓ Installing StorageClass
 ✓ Joining worker nodes
```

Check the Docker containers:

```bash
docker ps
```

You should see containers similar to:

```text
docker-k8-control-plane
docker-k8-worker
docker-k8-worker2
```

That is an important concept:

> Your Kubernetes nodes are themselves Docker containers.

# 10. Deploy a simple web application

Create:

```bash
cat > hello.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-web
spec:
  replicas: 2

  selector:
    matchLabels:
      app: hello-web

  template:
    metadata:
      labels:
        app: hello-web

    spec:
      containers:
        - name: nginx
          image: nginx:alpine

          ports:
            - containerPort: 80

          resources:
            requests:
              memory: "32Mi"
              cpu: "50m"

            limits:
              memory: "128Mi"
              cpu: "250m"

---
apiVersion: v1
kind: Service
metadata:
  name: hello-web
spec:

  type: NodePort

  selector:
    app: hello-web

  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080
EOF
```

Apply it:

```bash
kubectl apply -f hello.yaml
```

# 16. Scale from 2 pods to 5

Run:

```bash
kubectl scale deployment hello-web --replicas=5
```

Watch:

```bash
kubectl get pods -w
```

You should eventually get five pods.

Check:

```bash
kubectl get deployment hello-web
```

Expected:

```text
READY
5/5
```

This is one of Kubernetes's major features.

Instead of manually starting five containers, you tell Kubernetes:

```text
I want 5.
```

Kubernetes tries to keep five running.

# 17. Test Kubernetes self-healing

List the pods:

```bash
kubectl get pods
```

Pick one:

```text
hello-web-6765b6f945-abc12
```

Delete it:

```bash
kubectl delete pod hello-web-6765b6f945-abc12
```

Immediately run:

```bash
kubectl get pods
```

Kubernetes creates another pod.

Why?

Your Deployment says:

```yaml
replicas: 5
```

Kubernetes essentially says:

```text
I was told to maintain five pods.

I only have four.

Create another one.
```

That's **self-healing**.

# 23. Useful kubectl aliases on macOS

You're probably using `zsh`.

Add:

```bash

# Kubernetes
alias k='kubectl'
alias kgp='kubectl get pods'
alias kgs='kubectl get services'
alias kgn='kubectl get nodes'
alias kga='kubectl get all'
alias kaf='kubectl apply -f'
alias kdel='kubectl delete'
EOF
```

Reload:

```bash
source ~/.zshrc
```

Now:

```bash
k get nodes
```

Or:

```bash
kgp
```

instead of:

```bash
kubectl get pods
```

# 24. Create a cluster startup script

Create:

```bash
cat > create-cluster.sh <<'EOF'
#!/bin/bash

set -e

CLUSTER_NAME="docker-k8"

echo "================================"
echo "Checking Docker"
echo "================================"

docker info >/dev/null

echo "Docker is running."

echo
echo "================================"
echo "Creating Kubernetes cluster"
echo "================================"

kind create cluster \
  --name "${CLUSTER_NAME}" \
  --config kind-config.yaml

echo
echo "================================"
echo "Setting kubectl context"
echo "================================"

kubectl config use-context "kind-${CLUSTER_NAME}"

echo
echo "================================"
echo "Cluster nodes"
echo "================================"

kubectl get nodes -o wide

echo
echo "Cluster successfully created."
EOF
```

Make executable:

```bash
chmod +x create-cluster.sh
```

Use it:

```bash
./create-cluster.sh
```
